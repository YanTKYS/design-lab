# 折本：守る規則・変えてよい点・避ける誤用

出典：design-lab の10番目の比較デザイン `h-prime`（H′案。比較サイト本体の CSS / JS と、採用前の独立した3画面の試作）。ここには、別の業務へ移すのに必要な核だけをまとめた。色の値は [../assets/tokens.css](../assets/tokens.css) を正とする。

## 着想と説明のしかた

- 蛇腹に折った本（折本）の「面が右から左へひと続きに開く」「見開きで右頁から左頁へ読む」という**読む順の考え方**を、画面の並びに翻訳した。
- 説明するときは「折本に着想した独自のデザイン（仮称：折本、H′案）」とする。和本・経本の再現、公式のデザインシステム、日本の伝統様式の代表とは言わない。
- 実在の書物・経典の図版や写真は取り込まない。

## どの部品を使うか

業務にない部品は作らない。迷ったら使わない。

| 対象の画面 | 使う | 使わない |
| --- | --- | --- |
| 少数（数件〜十数件）を1件ずつ見分ける一覧：今日の予約、当番、審査中の数件 | 縦組みの面（右から左）、選んだ面から続く詳細 | — |
| 件数が多い・列を比べる一覧：数十件以上、金額や日付を縦に比べる | 表（横組み）。表題・章名・葡萄色の選択・フォーカスだけ折本にする | 縦組みの面、見開き送り |
| 2つのまとまりがある入力：利用内容と申込者、申請者と手続き | 見開き（右頁→左頁）、頁の右端の縦組みの章名、確認事項の葡萄色の帯 | — |
| まとまりが1つの入力・設定・ログイン | 1頁だけ（頁の地と縦組みの章名）、または頁なしで項目名の明朝と葡萄色の主操作だけ | 見開き |
| 既に集計がある画面 | 指標の面（起点を右端に）、区画の右端の縦組みの章題 | — |
| 集計がない画面 | 件数の文（「この日の予約 5件」） | 指標の面・グラフを新たに足すこと |

## 必ず守る規則

| 規則 | 内容 |
| --- | --- |
| 地と葡萄色 | 地は生成り（`--hp-ground`）。葡萄色（`--hp-grape`）は**今ここ**だけ：選んだ面・行、現在の手順や画面、主操作、確認事項の帯、起点の指標。ほかの面は2色の頁（`--hp-page-r` 先に読む／`--hp-page-l` 後に読む）と罫で分ける。 |
| 書体 | 表題・章名・項目名・縦組みの名前・大きな数字は明朝（`--hp-mincho`）。本文・補足・入力・操作はゴシック（`--hp-gothic`）。番号・日付・時刻は等幅（`--hp-mono`）。外部フォントは読み込まない。 |
| 右から左の面 | 少数の一覧は、1件を1つの縦長の面にし、先頭（最新・最初の時刻など）を**右端**に置いて左へ並べる。`flex-direction: row-reverse` を使い、**DOM の先頭＝右端の面＝Tab の最初**にする。面の上辺は交互に傾け（`--hp-tilt`）、面の間に折り目の線（`--hp-fold`）。 |
| 縦組みにするもの | 名前（申請者・団体名）・短い補足（種別・目的）・章名だけを `writing-mode: vertical-rl` にする。法人格（株式会社・特定非営利活動法人など）は小さく別の行にする。番号・日付・時刻・状態・操作は面の上下に横組みで置く。 |
| 選んだ面と詳細 | 選んだ面は葡萄色に反転し、詳細はその面の列の**直後**に、同じ葡萄色の全幅の帯として開く（色が下段へ続いて見える）。狭い幅で帯が多い場合は、選んだ帯の中に開いてよい（[patterns.md](patterns.md) の2）。開閉ボタンに `aria-expanded`・`aria-controls`。閉じたら開閉ボタンへフォーカスを戻す。 |
| 見開き | 2つのまとまりを右頁（先に読む）・左頁（後に読む）に置く。DOM は右頁→左頁の順に書き、`grid-template-areas: 'left right'` で見た目を右へ寄せる（**Tab も右頁→左頁**）。上辺は中央の綴じへ向けて少し上がる（`--hp-book-tilt`）。章名は頁の右端に縦組み（`--hp-page-title` の列）、入力欄の中は横書き。 |
| 確認の帯 | 送信前の同意・確認事項は、見開きの下の葡萄色の全幅の帯。左に章名、縦の区切り線、右に内容。 |
| 指標と区画 | 指標がある場合は、起点の値（受付件数・全件など）を右端の葡萄色の面にし、左へ読む。各区画は上に太罫（`--hp-section-rule`）、右端に縦組みの章題。月別などの時系列は左から右のままにし、向きを文字で示す。 |
| 件数とグラフ | グラフの棒は、隣に書く割合と同じ尺度（総数に対する構成比など）で描く。件数は棒の上か隣に文字で添え、棒だけで読ませない。棒は装飾（`aria-hidden`）にし、数値は文字で1回だけ読ませる。 |
| フォーカス | `outline: var(--hp-focus-ring)`、`outline-offset: var(--hp-focus-offset)`、`box-shadow: var(--hp-focus-halo)`。葡萄色の面・帯の上では `outline-color: var(--hp-light)`。選択の塗りとは別の形にする。`tabindex="-1"` へプログラムで移したフォーカスにも枠を出す（マウスで押したときの非表示は対象アプリの方針に合わせる）。 |
| エラー | 欄の上に「！エラー：理由と直し方」（`--hp-error`、太字）。欄の左に 4px の赤い帯、入力欄に 2px の赤い枠、`aria-invalid` とエラー文への `aria-describedby`。送信時は先頭の「入力エラーが n 件あります」（白の地・左に赤い帯）へフォーカスし、項目名のボタンで欄へ移す。葡萄色の帯の中のエラーは `--hp-error-on-grape` の文字と、帯の左端の淡い赤の帯。 |
| 状態 | 記号（受付 ○・途中 ◐・差し戻し △・完了 ●・取消/却下 × など）と文字の組。記号は `aria-hidden` でよい（文字で読む）。 |
| 狭い幅 | 目安 760px 未満で、縦組みの名前・補足を横組みに切り替える。面は上から下へ積む（先頭が上、傾きは `8px`）。見開きは右頁を上、左頁を下に積む。章名は短ければ細い列（40px）の縦組みのまま残してよい。表題を小さくし、主操作を全幅にする。ページ全体を横にはみ出させない。 |
| 中間の幅 | 面が狭くなりすぎる幅（目安 1100px 未満）では、面を2段に折り返す。上の段の右端が先頭（DOM の順のまま `flex-wrap: wrap`）。 |
| 部品の境界 | 入力欄・選択欄の枠は `--hp-control-line`（どの地でも 3:1 以上）。`--hp-line` は装飾の罫だけに使う。補助文字は `--hp-muted`（どの地でも 4.5:1 以上）。 |

## 変えてよい点

- **面の数とページ送り**：原本は1見開き8面と「← 次の8件／前の8件 →」の送り。件数が少ない業務では送りを作らず、全件を並べて折り返してよい。送りを作るなら、右から左に読むので「次」を左に置く。
- **見開きの有無**：まとまりが1つなら1頁でよい。3つ以上なら、2つを見開きにして残りを帯にするか、見開きを使わない。
- **頁の2色**：2色の差を弱める・1色にしてよい（その場合も先に読む頁を右に置く）。
- **縦組みにする要素**：名前を縦組みにしない判断もよい（長い名前が多い、読む人が縦組みに慣れていないなど）。その場合も右から左の順・葡萄色の選択・明朝の表題は残す。
- **傾きの量**：`--hp-tilt`・`--hp-book-tilt` を小さくしてよい。0 にすると折本らしさは弱まる。
- **表題の大きさ**：原本は 56px（狭い幅 36px）。業務画面の情報量に合わせて小さくしてよい。
- **状態の記号と色**：業務の状態に合わせて選ぶ。記号と文字は必ず組にする。
- **幅の切り替え**：画面全体なら `@media`、部品の領域で切り替えるなら `@container`。境目の値は内容に合わせる。

## 避ける誤用

- **縦組みの入力欄**、縦組みの本文・長文・メールアドレス・URL・番号・数値（IME の候補窓・カーソル移動・読み上げが不安定になり、読み違いも増える）。
- 画面全体を縦組みにする。表・時系列のグラフ・日付の前後操作（前日／翌日）を右から左へ反転する。
- 多い件数・列の比較が主の一覧に、縦組みの面や8面の送りを使う。
- 集計のない業務に、指標の面・グラフを飾りとして足す。
- `order` や `float` で見た目だけ入れ替え、Tab・読み上げの順と食い違わせる。
- 葡萄色で広い面を塗る（選択・現在地との区別が消える）、葡萄色の上に葡萄色のフォーカスの枠を出す。
- 傾き（`clip-path`）の内側に、番号・状態・操作・フォーカスの枠を食い込ませる。
- design-lab の CSS・HTML・JS（比較サイト専用の `main.js`、`data-action` の規約、状態モデル、URL の規約、8件の見開き番号の持ち方）を持ち込む。
- 対象アプリのデータ・保存・検証・ルーティングを、見た目の都合で変える。
- 外部のフォント・CDN・API を追加する。

## 確認の観点

- 右から左の面・見開き・指標で、見た目の順・Tab の順・読み上げの順が一致しているか。
- 長い名前（法人名・団体名）の縦組みが面の高さに収まるか。収まらない場合の文字の縮小・法人格の分離・狭い幅での横組み。
- 生成り・2色の頁・葡萄色の上の文字、補助文字、入力欄の枠の読みやすさ。
- IME の変換中の入力、キーボードだけでの主要操作、開閉後のフォーカスの戻り先。
- 右から左に読む部分と、左から右に読む部分（時系列・表）が混ざる画面で、向きの説明が足りているか。
- 明朝がない端末（ゴシックに落ちる）での見え方。
