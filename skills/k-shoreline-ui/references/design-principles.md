# 汀線：守る規則・変えてよい点・避ける誤用

出典：design-lab の12番目の比較デザイン `k-shoreline`（K案。比較サイト本体の CSS / JS と、採用前の独立した3画面の試作）。ここには、別の業務へ移すのに必要な核だけをまとめた。色の値は [../assets/tokens.css](../assets/tokens.css) を正とする。

## 着想と説明のしかた

- 水際の汀線の「陸と水が1本の線で接し、水が陸へ入り込んで続いていく」様子を、**画面の2つの領域の関係**に翻訳した。陸＝まとまりの名前（章名・選んだ行）、水＝その中身（入力欄・詳細）。
- 説明するときは「水際の汀線に着想した独自のデザイン（仮称：汀線、K案）」とする。実在の地図・海図・地形の再現、公式のデザインシステム、特定の地域を代表する様式とは言わない。
- 表題の等高線（[../assets/k-shore.svg](../assets/k-shore.svg)）は自作の図形。実在の地図・写真は取り込まない。

## デザインの核

**淡い緑の面で関連を示し、曲線で領域のつながりと境目を見せる。**

- 面：関連する2つ（選んだ行と詳細、章名と入力欄、集計の見出しと中身）を同じ系統の淡い緑でつなぐ。関連のない所は生成りの地のまま。
- 曲線：2つの領域が接する所にだけ、1本の汀線（細い曲線と面）を引く。曲線は境目の目印で、意味（選択・検証・状態）を持たせない。
- 面の色は弱い手がかりなので、選択・現在地・状態・エラーは**文字・記号・濃い緑の線・枠**でも示す。

## どの部品を使うか

業務にない部品は作らない。迷ったら使わない。

| 対象の画面 | 使う | 使わない |
| --- | --- | --- |
| 一覧から1件を選んで詳細を読む（数十件程度） | 選んだ行の面と濃い緑の線、行の直後の詳細（広い幅では右の列に見せてよい）、詳細の左端の汀線 | — |
| 一覧の列が多い・画面が狭い（右に列を取る余裕がない） | 選んだ行の直下に開く詳細（右の列なし） | 右の詳細の列 |
| 詳細を読まない一覧 | 面の色の選択（絞り込みの札）、罫 | 詳細の面・汀線 |
| 章ごとに入力する画面 | 章名の陸と入力欄の水際、間の汀線、エラーの一覧 | — |
| 項目が数個の入力・設定 | 1つの章（陸と水際）だけ、または汀線なしの入力欄 | 章の分割 |
| 既に推移（月別・週別など）の集計がある画面 | 実測の点・縦の線・件数と、目安の単調な曲線と面 | — |
| 集計がない画面 | 件数の文（表題の横など） | 指標の帯・推移の曲線を新たに足すこと |

## 必ず守る規則

| 規則 | 内容 |
| --- | --- |
| 地と面 | 地は生成り（`--k-ground`）。表題の段は `--k-hero`。陸（章名・選んだ行）は `--k-land`、水際の内側（入力欄の面）は `--k-area`、海（詳細・通知・集計の区画）は `--k-sea`。面は関連を示す所だけに置く。 |
| 書体 | 表題・章名・詳細の名前・大きな数字は明朝（`--k-mincho`）。本文・入力・操作はゴシック。番号・日付・件数の小さな数字は等幅（`--k-mono`）。 |
| 選んだ行 | 行の地を `--k-land` にし、左端に濃い緑の線（4px）。開閉ボタンの文言を「詳細」⇔「閉じる」で変え、`aria-expanded`。行の中に「表示中」などの文字を置くとよい。強制カラーでは地と `box-shadow` が消えるので、`Highlight` の枠で補う。 |
| 詳細の位置 | 詳細は DOM と Tab の順で**選んだ行の直後**（表なら次の行）。広い幅（目安：一覧の領域が 1000px 以上）では、CSS で右の列に見せてよい。その場合、**詳細を開く前から右の列を確保**し（「詳細を選ぶと、ここに表示します」）、開いた瞬間に表が狭まって行が折り返し直さないようにする。詳細は上端に濃い緑の線、左端に汀線、見出しの横に「詳細を閉じる」。高さを超える分は詳細の中でスクロールする。中間の幅・狭い幅では行の直下に開く。 |
| 章の陸と水際 | 章は左に章名の陸（`--k-land`、幅 `--k-rail-width`）、右に入力欄の水際（`--k-area`）。間に汀線の曲線（SVG、`preserveAspectRatio="none"` で章の高さに合わせて伸びる、`aria-hidden`）。曲線は章名・入力欄に重ねない。狭い幅では章名を上に、入力欄を下に積み、曲線は省くか下の角の丸みに置き換える。 |
| 推移の曲線 | 既に推移の集計がある画面だけ。各期間の**点・縦の線・点の真上の件数が実測**。点を通る滑らかな線（点線）と面は**目安**。補間は単調3次（Fritsch–Carlson など）で、隣の2点の範囲を超える山・谷を作らない。0件は基準線に置き、底上げしない。図の下に「点が各期間の件数です。線と面は目安です」と書く。SVG・点・線は `aria-hidden`、件数は文字で1回だけ読ませる。 |
| 内訳の棒 | 隣の割合と同じ尺度（総数に対する構成比）の細い棒。件数と割合は文字。0件の項目は一覧へのリンクにしない。 |
| 操作 | 主操作は濃い緑の塗り（`--k-green`）に白い文字、角はほぼ四角（2px）。副操作は濃い緑の枠。リンク・クリアは濃い緑の太字に下線。 |
| 絞り込みの札 | 下線だけの札。選んだ札は `--k-land` の地＋太字＋濃い緑の太い下線（＋✓）。札（ラジオ）は最初に1回だけ作り、描き直しでは `checked` と件数だけを更新する。 |
| フォーカス | `outline: var(--k-focus-ring)`、`outline-offset: var(--k-focus-offset)`、`box-shadow: var(--k-focus-halo)`。見えない `input` を使う札は見た目の側に枠を出す。`tabindex="-1"` へプログラムで移したフォーカスにも枠を出す。 |
| エラー | 上部に「入力エラーが n 件あります」（明朝の見出し、`--k-error`、左に太い線）へフォーカスし、項目名のボタンで欄へ。欄はエラー文（「エラー：」で始め理由と直し方）と 2px の枠、`aria-invalid`・`aria-describedby`。章名の陸にも「この章に n 件のエラー」を文字で出してよい。 |
| 状態 | 記号（○ ◐ △ ● × など）と文字。期限の超過などは文字（「3日過ぎています」）で示す。 |
| 狭い幅 | 目安 760px 未満で、表は行ごとに縦へ積む。並べ替えは列見出しの札の1組だけ（並べ替えできない列の見出しは隠す）。表題の装飾は表題の上の細い帯だけ。主操作は全幅。 |
| 部品の境界と補助文字 | 入力欄の枠は `--k-control-line`（どの面でも 3:1 以上）。`--k-line`・`--k-sep`・`--k-row`・`--k-shore` は装飾の罫と曲線だけ。補助文字は `--k-muted`、例示文字は `--k-placeholder`。 |
| 強制カラー | 面の色・SVG の曲線・`box-shadow` が消えても、選択（枠と文字）・現在地（太字と下線）・エラー（文言と枠）・フォーカス（外枠）が分かること。`forced-color-adjust: none` を画面全体に掛けない。 |

## 変えてよい点

- **詳細の置き場所**：右の列は必須ではない。列が多い・画面が狭い業務では、選んだ行の直下に開くだけでよい（面のつながりと汀線は残す）。
- **右の列の幅**（`--k-detail-width`）、章名の面の幅（`--k-rail-width`）。
- **表題の装飾**：k-shore.svg は省いてよい。使う場合も表題・件数・操作に重ねない。
- **曲線の本数と形**：汀線の SVG の曲線は1〜3本でよい。直線にはしない（汀線らしさがなくなる）。
- **推移の期間**：月別・週別など、業務の集計の単位に合わせる。
- **状態の記号**：業務の状態に合わせて選ぶ。記号と文字は必ず組にする。
- **幅の切り替え**：画面全体なら `@media`、部品の領域で切り替えるなら `@container`。

## 避ける誤用

- 緑の配色に塗り替えただけで、面のつながり・汀線の境目がない。
- 画面全体や関連のない所に面を塗る、曲線を飾りとして散らす、曲線を文字や入力欄の上に重ねる。
- 選んだ行を面の色だけで示す。曲線や面の色だけで状態・エラーを示す。
- 詳細を開いた瞬間に右の列を作り、表の幅が変わって選んだ行が見えなくなる。CSS の `order` などで詳細を行から離れた DOM の位置に置き、見た目と Tab の順を食い違わせる。
- 推移の曲線を実測のように見せる（点がない、件数がない、0件を底上げする、補間で山・谷を作る）。業務にない推移のグラフを足す。
- 描き直しのたびに絞り込みの札や並べ替えのボタンを作り直し、操作した部品のフォーカスを失わせる。
- design-lab の CSS・HTML・JS（比較サイト専用の `main.js`、`data-action` の規約、状態モデル、URL の規約）を持ち込む。
- 対象アプリのデータ・検索・検証・保存・URL・ルーティングを、見た目の都合で変える。
- 外部のフォント・画像・CDN・API を追加する。

## 確認の観点

- 広い幅で詳細を開く前後に、表の幅と選んだ行の位置が変わらないか。詳細が画面の高さを超えるときに「詳細を閉じる」が見えるか。
- 中間の幅・狭い幅で、詳細が選んだ行の直下に開くか、Tab の順が行 → 詳細 → 次の行か。
- 章の汀線の曲線が、章の高さ（エラー文が増えたとき）に合わせて伸び、章名・入力欄に重ならないか。
- 推移の曲線で、0件の期間が基準線にあるか、点と件数が合っているか、補間が山・谷を作っていないか。
- 淡い面の上の補助文字、入力欄の枠のコントラスト。強制カラーでの選択・エラーの見え方。
- 矢印キー・Tab、絞り込み・並べ替え・開閉・エラー後のフォーカス、IME の変換中の検索。

## 原本から変えた値

| トークン | 原本（k-shoreline.css） | Skill | 理由 |
| --- | --- | --- | --- |
| `--k-control-line`（新設） | 入力欄の枠に `--k-line`（`#9fb7ab`） | `#6e8880` | 原本の値は入力欄の面（`--k-area`）で 1.95:1、入力欄の地で 2.1:1。Skill の値は生成り 3.6:1、入力欄の面 3.5:1、海 3.2:1、入力欄の地 3.8:1 |
| `--k-placeholder`（新設） | 例示文字に `#6f857e` | `#5b746e` | 原本の値は入力欄の地で 3.9:1。Skill の値は 5.0:1 |
| `--k-land`（改名） | `--k-rail` | 同じ色 `#d6e7da` | 「陸」の役割が分かる名前にした |

そのほかの主な組み合わせ（計算値）：本文 `--k-ink` は生成り 10.9:1・陸 9.0:1・海 9.7:1、濃い緑 `--k-green` は生成り 7.1:1・陸 5.9:1、白い文字の濃い緑の塗り 7.6:1、補助文字 `--k-muted` は陸 4.75:1・海 5.1:1、エラー `--k-error` は陸 5.2:1・入力欄の地 6.6:1。`--k-line`（生成り 2.0:1）は装飾の罫だけに使う。
