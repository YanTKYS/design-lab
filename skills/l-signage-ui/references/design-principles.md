# 標示盤：守る規則・変えてよい点・避ける誤用

出典：design-lab の13番目の比較デザイン `l-signage`（L案。比較サイト本体の CSS / JS と、採用前の独立した3画面の試作、改良したフォームの検討 `docs/l-form-study/`）。ここには、別の業務へ移すのに必要な核だけをまとめた。色の値は [../assets/tokens.css](../assets/tokens.css) を正とする。

## 着想と説明のしかた

- 駅や窓口の案内表示の「暗い盤面を区画に分け、今の状態だけを点灯させる」「数字をドットで点灯させる」という**見せ方の考え方**を、画面の現在地の示し方に翻訳した。
- 説明するときは「案内表示（標示盤）に着想した独自のデザイン（仮称：標示盤、L案）」とする。特定の鉄道・空港・メーカーの表示器の再現、公式のデザインシステムとは言わない。
- ドット文字の字形（[../assets/dot-digits.js](../assets/dot-digits.js)）は自作。実在の表示器の字形は取り込まない。

## デザインの核

**暗い盤面を区画に分け、今の状態だけを琥珀で点灯させる。**

- 盤面：暗い緑黒の地（`--ls-ground`）に、少しずつ明るさの違う区画を、細い継ぎ目（`--ls-gap`、`--ls-seam`）で組む。
- 点灯：琥珀（`--ls-amber`）は**現在地**だけ。選んだ状態の区画、選んだ行とその直後の詳細の左の帯、フォームの現在の手順と手順の罫、主操作。同じ画面で琥珀が並ぶのは「今」と「次にすること」に限る。
- ドット文字：件数・手順の番号などの補助の表示。読む情報は普通の文字で、ドット文字は盤面らしさの装飾。

## どの部品を使うか

業務にない部品は作らない。迷ったら使わない。

| 対象の画面 | 使う | 使わない |
| --- | --- | --- |
| 状態ごとの件数を一目で見せたい一覧（数種類の状態） | 状態の盤面（ラジオの区画＋ドット文字の件数）、台帳の表、選んだ行の直後の詳細 | — |
| 状態が多い（8種類以上）・件数が4桁を超える一覧 | 普通の絞り込み（札やセレクト）と台帳の表、選んだ行と詳細 | 状態の盤面のドット文字（幅が足りない） |
| 手順のある入力（2〜4段） | 左の列の現在の手順と琥珀の罫、章名の枝、右の列の入力欄、下段の「次の手順」と主操作 | — |
| 手順のない短い入力・設定 | 暗い区画と入力欄、生成りのフォーカス、エラーの形 | 現在の手順の区画・下段の手順 |
| 既に件数・推移を扱う画面（件数が数十件まで） | 「1目盛り＝1件」の点灯と右の件数、指標の盤面（ドット文字） | — |
| 件数が多い（1項目で数百件など）集計 | 普通の棒グラフや表（目盛りは細かくなりすぎる） | 「1目盛り＝1件」 |
| 集計がない画面 | 件数の文 | 指標の盤面・目盛りを新たに足すこと |
| 明るい部屋で長時間読む文書・印刷する帳票 | 使わないことを検討する（暗い画面が向かない場合がある） | — |

## 必ず守る規則

| 規則 | 内容 |
| --- | --- |
| 盤面と区画 | 地は `--ls-ground`、区画は `--ls-bar`・`--ls-rail`・`--ls-cell`、継ぎ目は `--ls-gap`。盤面の上下は太い罫（`--ls-frame`、3px）。明るい上部の帯（`--ls-top`）は任意。 |
| 琥珀の使い方 | 琥珀は現在地と主操作だけ。琥珀の面の上の文字・枠・フォーカスは `--ls-ink`。琥珀の上にエラーの色・補助文字の色を置かない。 |
| 状態の盤面 | 状態ごとに1つの区画。中身は**本物のラジオ**（見えない `input` を区画いっぱいに重ねる）と、状態名・ドット文字の件数・読み上げ用の「n件」。選んだ区画は琥珀の地＋✓＋太字。ラジオは**最初に1回だけ作り**、描き直しでは `checked` と件数だけを更新する（作り直すと矢印キーで続けて選べない）。 |
| ドット文字 | 5×7 の点。消灯の点（不透明度 0.1、琥珀の上では 0.13）で桁の枠が見える。1桁は**左を消灯の桁で埋め**、0 では埋めない（「08」と読めないように）。SVG は `aria-hidden`、同じ数値を `visually-hidden` などの文字で1回だけ置く。数値が読めなくなる大きさ（高さ 18px 未満）にしない。3桁以上で区画に入らないときは、縮める・普通の数字に替える・省く。 |
| 選んだ行と詳細 | 選んだ行は琥珀の地・`--ls-ink` の太字。詳細はその行の**直後**（表なら次の行）に開き、左に琥珀の帯（`inset 5px 0 0`）。詳細の小見出し・項目名は琥珀の文字（暗い地の上で 7.7:1）。開閉ボタンは「詳細」⇔「閉じる」と `aria-expanded`。開いたら詳細の見出しへ、閉じたら開閉ボタンへフォーカスを移す。 |
| フォームの手順 | 左の列（`--ls-rail-width`）の上に現在の手順の区画（琥珀の地にドット文字の番号＋手順名＋「現在」、読み上げ用の「手順 n / m」）。その下に琥珀の縦の罫（3px）を通し、各章名へ短い横の枝を出す（最後の章で罫が止まる）。右の列に入力欄の区画。下段の左に「次の手順」（次の番号を大きく）、右に主操作、間を琥珀の点線でつなぐ。手順の数は業務に合わせる。 |
| フォーカス | `outline: var(--ls-focus-ring)`、`outline-offset: var(--ls-focus-offset)`。琥珀の区画の中では `outline-color: var(--ls-ink)`。見えない `input` を使う区画は、見た目の側に枠を出す。エラーの欄（チェックボックスなど）の赤い印は `outline` ではなく `box-shadow` にし、フォーカスの外枠と重ねない。 |
| エラー | 上部に「エラー」の札と「入力エラーが n 件あります」（左に赤い帯）へフォーカスし、項目名のボタンで欄へ。欄は「!」の印＋「エラー」＋理由と直し方、2px の枠、左に赤い帯。章名の下に「エラー n件」。`aria-invalid`・`aria-describedby`。 |
| 状態 | 記号（○ ◐ △ ● × など）と文字。琥珀や色の違いだけで状態を示さない。 |
| 1目盛り＝1件 | 既に件数を扱う画面だけ。1項目の目盛りの数は、最大値を5の倍数に切り上げた数（どの項目でも1目盛りは1件のまま。最多の値に合わせて縮めない）。点灯の数＝件数。件数は目盛りの右に普通の文字で置く。目盛りは `aria-hidden`。0件は点灯なしで、一覧へのリンクにしない。割合を書くときは分母を明記する。 |
| 狭い幅 | 目安 760px 未満で、状態の盤面は2列（3列では状態名が1字ずつ折り返す）、状態名は折り返さない。表は行ごとに縦へ積み、並べ替えは列見出しの札の1組だけ（並べ替えできない列の見出しは隠す）。フォームは 640px 未満で1列にし、手順の罫は左端に通したまま章名を欄の上に置く。主操作は全幅。 |
| 部品の境界と補助文字 | 入力欄は `--ls-field` の地に `--ls-field-line` の枠（区画の地で 4.3:1）と `--ls-field-under` の下線。補助文字 `--ls-muted` はどの区画でも 4.5:1 以上。例示文字は `--ls-placeholder`。 |
| 強制カラー | ドット文字と目盛りだけ `forced-color-adjust: none` にし、点灯を `CanvasText`、消灯を薄い `CanvasText`（目盛りは `Canvas` の地に枠）で描き分ける。選んだ区画・選んだ行・現在の手順は `Highlight` の枠で補う。本文・入力欄・操作は強制カラーのまま。画面全体に `forced-color-adjust: none` を掛けない。 |

## 変えてよい点

- **明るい上部の帯**：なくてよい。ある場合は組織名・システム名・利用者だけ。
- **状態の盤面の区画の数・並び**：業務の状態の数に合わせる（「すべて」を含めて 3〜7 区画が目安）。
- **ドット文字の大きさと桁数**：区画の大きさに合わせる。番号（整理番号など）は3桁にそろえてよい（左は消灯の桁）。
- **手順の数**：2〜4段。手順がない画面では現在の手順の区画を使わない。
- **琥珀の色味**：対象アプリの警告色と紛らわしい場合は、明るさを保って色味を少し変えてよい（`--ls-ink` との 7:1 以上を保つ）。
- **幅の切り替え**：画面全体なら `@media`、部品の領域で切り替えるなら `@container`。

## 避ける誤用

- 暗い色に塗り替えただけで、区画・琥珀の現在地・ドット文字の補助の関係がない。
- 琥珀をあちこちに使う（見出し・飾り・すべてのボタン）。現在地が分からなくなる。
- ドット文字だけで数値を示す（読み上げ・拡大・強制カラーで読めない）。ドット文字と普通の文字の両方を読み上げさせる。
- 1桁を 0 で埋める（「08」）。3桁以上を無理に小さいドットで詰め込む。
- 状態の盤面を `div` とクリックだけで作る（キーボード・読み上げで使えない）。描き直しでラジオを作り直す。
- エラーの赤い印を `outline` で付け、フォーカスの外枠を消す。琥珀の上にエラーの色を置く。
- 業務にない指標・目盛り・盤面の区画を足す。件数の多い集計に「1目盛り＝1件」を使う。目盛りの1目盛りの意味を項目ごとに変える。
- 画面全体に `forced-color-adjust: none` を掛ける。
- design-lab の CSS・HTML・JS（比較サイト専用の `main.js`、`data-action` の規約、状態モデル、URL の規約）を持ち込む。
- 対象アプリのデータ・検索・検証・保存・権限・URL・ルーティングを、見た目の都合で変える。
- 外部のフォント・画像・CDN・API を追加する。

## 確認の観点

- 琥珀の区画が「今」と「次」だけか。ドット文字と普通の文字の数値が一致しているか（0件・1桁・2桁・3桁）。
- キーボードで状態の区画を選んだ後もフォーカスが残り、矢印キーで続けて選べるか。開閉・エラー後のフォーカス。
- 生成りのフォーカスが、暗い区画・琥珀の区画・エラーの欄のどれでも見えるか。
- 狭い幅で、状態名が1字ずつ折り返さないか、ドット文字が区画に入るか、表の並べ替えが1組か。
- 強制カラーで、ドット文字・目盛り・選択・現在地・エラーが分かるか。
- 利用する環境：明るい事務室での長時間の作業、印刷（暗い地はそのまま印刷に向かない）。

## 未検証の条件

- 明るい部屋・長時間の利用で、暗い画面が疲れにくいか、見やすいか。
- 印刷（暗い地と琥珀の面）。印刷が必要な業務では、印刷用の明るいスタイルを別に用意するか、このデザインを使わないことを検討する。
- 実際の OS の強制カラー（Windows のハイコントラスト）、スクリーンリーダー、色覚の違いによる琥珀の見え方。
