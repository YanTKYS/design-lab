# 案E・F・G の設計資料（最小）

[追加探索の比較に戻る](README.md)

案を選んだ後に実装担当へ渡す前提の、最小限の記録。名称はすべて仮称。モックの HTML・CSS は見た目の参照で、実装の正本ではない（[mock/](mock/)）。値は共通モデル（`buildModel`・`buildDashboardModel`）から生成した。

## 案E　仕次ぎ（しつぎ）

**着想源。** 泡盛は3年以上熟成させたものを「古酒（くーす）」と呼び、3年・5年・7年のように貯蔵年数を商品名に明記するものも多い。古酒を育てる方法として、1年に1度程度、少し古酒を抜いて若い酒を注ぎ足し、質を保ちながら味わいを深める「仕次ぎ」が紹介されている。（[おきなわ物語「古酒（くーす）って何？」](https://www.okinawastory.jp/feature/awamori/kusu)）

**核の規則。**
1. **経過した時間で段を分ける。** 処理待ちの記録を、受付からの経過日数（基準日から計算）で「61日以上／31〜60日／15〜30日／8〜14日／7日以内」の段に分け、古い段を上に置く。
2. **年数を名乗る。** 各行の先頭は経過日数（大きな数字）。処理期限は「期限まで n日」「！期限を n日超過」と文字で併記する。
3. **古い段から手を入れる。** 一覧の上の目盛（段ごとの件数と、期限超過の件数）から、古い段へ直接移れる。段は古いほど深い色にする（色だけでなく段の名前と順序でも示す）。

仕次ぎは「古いものに定期的に手を入れて保つ」工程で、「古い順に処理する」という意味ではない。経過時間を段にして古いものから手当てする、という読み替えはこの案の創作。

**色・書体・読み順・操作。** 紙色の地（`#f8f7f3`）、墨（`#1d2024`）。段の色は新しい順に `#e6ebef`→`#cbd5dd`→`#a3b2bf`→`#56687a`→`#243240`（深い2段は白字）。操作は青（`#0b56a4`、白地で 7.3:1）、期限超過は赤（`#b3261e`、6.5:1）＋「！」。ゴシック1系統、経過日数は 24px の太字。読み順は「目盛（どの段に何件）→ 段の見出し → 経過日数 → 受付番号（詳細を開く）→ 期限」。主操作は検索、選択は青の塗り＋✓。

**他の画面への展開（方向だけ）。**
- ダッシュボード：処理待ち19件を経過日数の段で積んだ帯にし、期限超過の件数を並べる。段から一覧の同じ段へ移る。
- フォーム：希望日を選んだら「基準日から n日後」を文字で添える程度にとどめる。この案の特色は一覧と集計にある。

**375px。** 目盛は縦の5行。台帳は1件ずつの塊にし、左端に段の色の帯、経過日数を大きく置く。段の見出しは区切りとして残す。

**向く用途。** 処理期限の管理が重い窓口業務、問い合わせ・苦情・修繕依頼など滞留が問題になる受付台帳。

**弱点。**
- 一覧の既定の並び（受付日の新しい順）を変える。列見出しでの並べ替え（共通の `sort` 状態）と段の関係を決める必要がある。
- 処理完了の記録には「経過」の意味が薄い。「すべて」を選んだときは段の外にまとめる。
- 経過日数・期限までの日数は、共通モデルにない派生値（`REFERENCE_DATE` と `receivedAt`・`dueAt` から計算）。

## 案F　透かし（すかし）

**着想源。** 花ブロックは沖縄の建築に使われる装飾的なコンクリートブロックで、主に外壁に用いられる。透かし模様によって通気性を保ちながら強い日差しを遮り、透かし部分から時々の光が差し込む。（[岐阜女子大学 デジタルアーカイブ研究所「沖縄の生活文化 花ブロック」](https://digitalarchiveproject.jp/press/%E6%B2%96%E7%B8%84%E3%81%AE%E7%94%9F%E6%B4%BB%E6%96%87%E5%8C%96%E3%80%80%E8%8A%B1%E3%83%96%E3%83%AD%E3%83%83%E3%82%AF/)）

**核の規則。**
1. **遮っても、消さない。** 絞り込みで外れた記録を一覧から消さず、連続する分を1本の「壁」にまとめて元の並び順の位置に残す。壁には件数・日付の範囲・状態ごとの内訳を文字で書く。
2. **1マス＝1件の透かし。** 壁は外れた記録の数だけマスを並べる。マスの透かしの形で処理状態を示す（受付済＝丸、審査中＝半円、補正依頼＝ひし形、承認済＝十字、却下＝横の切れ目）。形と文字で示し、色は変えない。
3. **開口から光を通す。** 該当する記録は白い行（開口）として、左端に光の色の細い線を持つ。壁の「このn件も表示」で、その範囲だけを開ける。

**色・書体・読み順・操作。** コンクリートの淡い灰の地（`#f3f2ee`）、白い行、墨（`#202124`）。壁の帯は `#e7e5df`、マスは `#8a847a`、透かしの光は `#fff3c4`（マスと光の差 3.3:1）。操作は深い青緑（`#0d6767`、白地で 6.7:1）。フォーカスは墨の輪＋外側に日差しの黄。読み順は「件数（71件中 8件）と『壁として残している』の説明 → 開口の行 → 壁の件数と範囲」。壁を開く操作は文字ボタン、全部を開くのは副ボタン。

**他の画面への展開（方向だけ）。**
- フォーム：送信後、問題のない項目を「入力済み n項目」の壁にたたみ、エラーの項目だけを開口として元の位置に残す。
- ダッシュボード：内訳の1つを選ぶと、ほかを壁（淡いマス）にして位置と件数を残す。

**375px。** 壁のマスは折り返す。長い壁（例：36件）は1行分のマスと「ほか n件」の文字に縮め、件数と範囲の文字は必ず残す。開口の行は1件ずつの塊。

**向く用途。** 絞り込みや検索を多用する一覧。特に「絞り込んだまま忘れる」「結果が全体のどこにあるか分からない」ことが問題になる画面。

**弱点。**
- 一覧の描画が「該当」と「非該当のまとまり」の交互になり、実装と読み上げの設計が増える。壁は「該当しない6件、9月25日〜9月15日、展開ボタン」と読めるようにする。
- 開いた壁の範囲は新しい画面状態になる。URL に載せるかを決める必要がある。
- 該当が1件だけの検索では壁が大部分を占め、利点が薄い。
- マスが小さく、透かしの形の見分けは目に頼る。読み上げと文字の内訳が主で、マスは補助にする。

## 案G　座と裏座（ざとうらざ）

**着想源。** 沖縄の伝統的な民家は石垣で囲まれ、門の奥のヒンプン（衝立）を回り込むと開放的な空間がある。母屋には玄関らしいものがなく、開口部の大きな縁側から主も客も各部屋に上がる。間取りは一番座・二番座・三番座が縁側に面して並び、それぞれの裏側に「裏座」がある。（[おきなわ物語「沖縄古民家 ミニ辞典」](https://www.okinawastory.jp/feature/kominka/kominka_jiten)）

**核の規則。**
1. **数値の真裏に内訳を置く。** 主要な指標を縦の列（座）にし、その下に内訳（裏座）を同じ列で置く。受付件数の裏に月別と申請種別、処理待ち件数の裏に受付済・審査中・補正依頼、処理完了件数の裏に承認済・却下と処理完了率。
2. **合計を同じ列で確かめられる。** 内訳の下に「4＋8＋7＝19件」のような式を置く。指標と内訳が離れないので、視線が画面を横断しない。
3. **縁側から各座へ上がる。** 集計条件の帯（縁側）がすべての座に面し、各座の表に一覧への入口を1つ置く。座の境は太い柱、表と裏の境は二重の敷居線にする。

部屋の用途（客間・仏間など）は画面に割り当てない。参照したのは「表の部屋の裏に裏座がある」「縁側からどの部屋へも上がれる」という構成だけ。

**色・書体・読み順・操作。** 漆喰のような白（`#fdfcf8`）の表、少し沈んだ裏座（`#f0ece2`）、木の柱（`#6b4a30`）。操作は深い緑（`#1f5a49`、裏座上で 6.8:1）、内訳の棒は木の色の淡い茶（`#8a7a63`、非文字 3.5:1）。指標は 52px の太字。読み順は「縁側（条件）→ 各座の表（指標・説明・一覧へ）→ 敷居 → 裏座（内訳・合計式）」。列の順は 受付 → 処理待ち → 処理完了 で、左から右へ処理が進む。

**他の画面への展開（方向だけ）。**
- 一覧：件数（表）の真下に処理状態の内訳（裏）を置いてから台帳にする。各行の詳細は行の真下（その記録の裏座）に開く。
- フォーム：まとまりごとに、表（入力済みの要約1行）と裏（入力欄）を持つ。確認画面は表だけを並べ、「修正」で裏へ入る。

**375px。** 座を縦に積み、どの座も「表→敷居→裏座」の順を保つ（[補助画像](images/g-dashboard-375.png)）。柱は各座を囲む枠になる。

**向く用途。** 指標とその内訳を照合する集計画面全般。報告前に合計の整合を確かめたい場面。

**弱点。**
- 3列の高さがそろわず、短い列の下が空く（1280pxでは処理待ちの列）。
- 処理完了率を処理完了の裏座に入れたため、4指標が横一列に並ぶ形式に慣れた人には完了率が見つけにくい可能性がある。
- 一覧・フォームへの展開は、ダッシュボードほど特色が強くない。
