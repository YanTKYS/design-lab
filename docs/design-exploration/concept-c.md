# 案C「素地と釉（きじとくすり）」設計資料

[探索の概要に戻る](README.md)

実装担当者向けの資料。名称は仮称。モックは [mock/c-list.html](mock/c-list.html)・[mock/c-form.html](mock/c-form.html)・[mock/c-dashboard.html](mock/c-dashboard.html)（[c.css](mock/c.css)）で、値は共通モデルから生成している。モックの HTML・CSS は見た目の参照で、実装の正本ではない。

## 1. 設計の核

**釉は、手に触れるところにだけ掛ける。**

壺屋焼では、日常で手に取る器（食器・酒器・花器）に釉薬を掛けた「上焼」が主流で、釉薬には水漏れを防ぎ汚れをつきにくくする効果があると説明されている。一方、甕や壺など大型の容器が中心の「荒焼」は釉薬を掛けず、陶土の風合いをそのまま活かす。（[おきなわ物語「やちむんとは」](https://www.okinawastory.jp/feature/yachimun/whatisyachimun)）

この区別を、画面の**操作できるもの／読むだけのもの**の区別に置き換える。

| 区分 | 画面で当たるもの | 見た目 |
| --- | --- | --- |
| 釉（上焼） | リンク、ボタン、入力欄、選択肢、並べ替え、ナビ、詳細を開く受付番号 | 白化粧の面（`#fffdf8`）と呉須の色（`#1f4f96`）。角を 4px 丸める。下端に濃い呉須の「釉だまり」 |
| 素地（荒焼） | 記録の値、件数・割合、見出し、グラフの棒、状態の印、説明文 | 陶土の地（`#efe6d9`）に鉄色の文字。棒・印・罫は土色。角は丸めない |

この規則は例外を作らないことに価値がある。**呉須色のものは必ず押せ、押せるものは必ず呉須色を持つ**。エラーの鉄赤だけが例外の色で、必ず「エラー」の文字と組み合わせる。

## 2. 情報階層と読み順

1. 画面名（素地の上に大きな文字、下に二本の線彫り）
2. 条件（検索・絞り込み・集計条件）：すべて釉の面なので、押せる場所として最初に目に入る
3. 結果の件数と、いま効いている条件（文字）
4. 記録・数値（素地。読むための面）
5. 選んだ記録の詳細（白化粧の盆）

色の強さが「操作できる順」を示し、文字の大きさと太さが「読む順」を示す。この二つを混ぜない。

## 3. 画面別の構成

### 申請一覧

- 上から：キーワード（入力欄＋「検索」主ボタン）→ 処理状態の選択肢（すべて／受付済／審査中／補正依頼／承認済／却下、各件数付き）→ 件数と条件（「71件中 8件を表示」「絞り込み中：処理状態『審査中』」「条件をクリア」）→ 台帳。
- 台帳の列は共通モデルの5列（受付番号・申請者・申請種別・受付日・処理状態）。列見出しは並べ替えボタン（呉須、矢印、`aria-sort`）。
- **受付番号が詳細を開くボタン**（`aria-expanded`）。行全体はクリック対象にしない（押せる範囲を呉須の部分に限るため）。
- 開いた記録は、行の左端に呉須の帯（5px）と「詳細を表示中」の文字。
- **詳細の位置**：幅 960px 以上は右の「盆」（幅 360px、`position: sticky`）。台帳を見たまま照合できる。960px 未満は選んだ記録の直下に同じ盆を差し込む。開いたら盆の見出しへフォーカス、閉じたら受付番号のボタンへ戻す。
- 詳細の項目：受付番号・申請者・ふりがな・申請種別・担当課・受付日・受付方法・処理期限・処理状態・備考（空は「なし」）。
- 保持する状態：キーワード、処理状態、並べ替え、開いている詳細、ダッシュボードから引き継いだ範囲（既存の `buildModel` の state をそのまま使う）。引き継ぎ中は件数の行に条件を文字で出し、解除ボタン（文字ボタン）を置く。

### 新規申請

- 1列（最大 720px）。PCでも2列にしない。余白は削らず、項目間 20px、まとまり間 30px。
- 手順表示「1 入力 ― 2 確認 ― 3 完了」。現在の手順は押せないので素地（鉄色の太字＋土色の下線）。
- 送信後のエラーのまとめ：鉄赤の 3px 枠、見出し「エラー：n件の入力を直してください」、各項目へのリンク（呉須）。送信直後にまとめへフォーカス（`tabindex="-1"`）。
- まとまり：申請者情報（氏名・ふりがな・メール・電話）／手続きの内容（種別・希望日・申請内容）／確認事項（同意）。見出しの上に二本の線彫り。
- 項目：ラベル（太字）＋「必須」「任意」（土色の枠の小さな札。押せないので呉須にしない）→ 補足 → エラー文（「エラー：」＋ `MESSAGES` の文言）→ 入力欄。エラーの項目は左に鉄赤の 4px 線、入力欄の枠も鉄赤。
- 主操作は最後に1つ「確認へ進む」（呉須の塗り、高さ 54px）。確認画面（モックなし）は同じ1列で、項目名と値を素地の表に並べ、各行に「修正」（呉須の文字ボタン）、最後に「申請する」（主）と「入力に戻る」（副）。完了画面は受付の文言と「申請一覧へ」（リンク）。

### ダッシュボード

- 集計条件：対象期間・担当課のセレクト（釉）、「リセット」（副ボタン）、右に基準日と期間の範囲（素地）。
- 4指標は**箱に入れない**。1行に並べ、間を縦の二重の線彫り（4px double、土色）で区切る。数値（46px、鉄色）は押せないので素地。各指標の下に「〜の一覧を見る」（呉須のリンク）。処理完了率には一覧がないので「（一覧はありません）」と書き、リンクを置かない。
- 月別の受付件数：土色の縦棒＋棒の上に件数の文字。棒は押せないため呉須を使わない。
- 処理状態の内訳・申請種別の内訳：行ごとに「印（状態のみ）・名称（呉須のリンク）・件数・割合」、下に土色の細い棒。名称のリンクで、既存の `listStateFor` の条件を引き継いで一覧へ移る。

## 4. 幅による変形

| 幅 | 変形 |
| --- | --- |
| 960px 以上 | 一覧の詳細は右の盆。集計は月別と状態別を2列 |
| 600〜959px | 詳細は選んだ記録の直下。集計は1列。4指標は2×2（区切りは縦横の線彫り） |
| 600px 未満 | ナビは2×2の釉のタブ（隠さない）。台帳は1件ずつの塊（1行目に受付番号と状態、次に申請者（太字）・種別・受付日）。主ボタンは全幅。基準日は条件の下 |

情報を消さない。利用者名（「審査担当 A」）も狭い幅で帯の中に残す。

## 5. 色・書体・余白・罫

| 名前 | 値 | 用途 |
| --- | --- | --- |
| 素地 | `#efe6d9` | ページの地 |
| 荒焼の帯 | `#4a3328` | 上部の帯（文字 `#f4ece2`、10.0:1） |
| 鉄 | `#2b1f18` | 本文（素地上 12.9:1）、フォーカスの輪 |
| 鉄（薄） | `#5d493c` | 補足（6.8:1） |
| 赤土 | `#9a5b3c` | 線彫り・棒・状態の印（4.3:1。文字には使わない） |
| 赤土（淡） | `#c7ab90` | 行の罫 |
| 白化粧 | `#fffdf8` | 押せる面（入力欄・ボタン・タブ・詳細の盆） |
| 呉須 | `#1f4f96` | 押せるものの色（素地上 6.5:1、白化粧上 7.9:1、主ボタンの白文字 8.0:1） |
| 釉だまり | `#133a72` | 主ボタン・選択中の下端 4px |
| 鉄赤 | `#a3261b` | エラーだけ（素地上 6.0:1） |

- 書体：ゴシック1系統（`BIZ UDPGothic` → ヒラギノ角ゴ → 游ゴシック → Noto Sans JP → メイリオ）。明朝は使わない（「糸の交点」との区別）。見出しは太さと大きさで区別。数値は `tabular-nums`。
- 余白：外余白 52px／24px／16px。まとまり間 30px。
- 罫：画面名とまとまりの区切りは「線彫り」（1px＋2px 空き＋1px の土色）。表の見出し下は 3px double。行は 1px 淡土色。
- 角：釉の面は 4px、素地の面・エラー枠・札は 0。

## 6. 状態・操作の表し方

- **操作の優先順位**：主（呉須の塗り＋白文字＋下端の釉だまり）＞副（白化粧＋呉須の枠＋下端 3px）＞文字（呉須の下線）。1画面の主ボタンは原則1つ。
- **選択**：呉須の塗り＋白文字＋「✓」（絞り込みの選択肢、ナビの現在地）。
- **フォーカス**：鉄色 3px の輪＋白化粧 3px の隙間（`outline` と `box-shadow`）。選択（呉須の塗り）とは色も形も違う。プログラムで移したフォーカス（エラーのまとめ、詳細の見出し）にも出す。
- **処理状態**：色を使わず、形の印＋文字。受付済 ○、審査中 ◐（左半分を塗る）、補正依頼 △、承認済 ●、却下 ×。印は SVG（字形の差を避ける）、`aria-hidden`。
- **エラー**：鉄赤の文字「エラー：」＋理由、項目の左線、入力欄の枠。色だけにしない。

## 7. ヘッダーを除いても残る個性

帯を外しても、(1) 押せるものだけが白く光って呉須の縁を持つ、(2) 数値と記録が箱に入らず線彫りで区切られる、(3) 状態が色ではなく窯印のような形で並ぶ、の3点で本文が識別できる。[本文だけの比較](README.md#本文だけで比べる)。

## 8. アセットとライセンス

- 画像・模様・外部フォント・CDN・アイコン集は使わない。上部の輪の印、状態の印、線彫り、棒はすべて CSS と数行の SVG（基本図形）で描く。
- 器の写真、特定の陶工の図柄（魚紋・唐草など）、窯元のロゴは使わない。色は画面のための選色で、器の測色値ではない。

## 9. 実装時に判断が残る箇所・リスク

| 箇所 | 内容 | 推奨 |
| --- | --- | --- |
| 状態の見分け | 色を使わないため、台帳で「補正依頼」を素早く拾うのは色分けより遅い可能性 | 印の形を変えずに、並べ替え・絞り込みで補う。利用者の確認で遅いと分かれば、補正依頼だけ印を太くする（色は足さない） |
| 規則の維持 | 将来、装飾や強調に呉須を使いたくなる | 「呉須＝押せる」をレビューの確認項目にする。画面内の呉須色の要素がすべて `a`・`button`・入力要素かを自動で確かめられる |
| 呉須の文字とリンク | 呉須の文字は下線と太字で示す。本文中のリンクが増えると読みにくい | 本文中のリンクは最小限にし、操作は行末・まとまりの最後に寄せる |
| 暖色の地 | 長時間の照合で、生成りの地がまぶしい／くすんで見える可能性 | 実機で確認。地の明度は変えても、白化粧（押せる面）との差は残す |
| 詳細の盆の幅 | 360px では長い法人名・備考が折り返す | 960〜1100px では盆を 320px に縮めるか、台帳の列（申請種別）を折り返す |
| 撮影環境の書体 | モックの画像は BIZ UD フォントのない環境（代替のゴシック体）で撮影 | Windows（BIZ UDPゴシック）で字幅と折り返しを確認する |
