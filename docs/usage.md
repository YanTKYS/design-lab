# 使い方と利用仕様

[README に戻る](../README.md)

比較画面の操作、共有 URL、集計値の読み方を説明します。デザインごとの特徴は[デザイン比較ガイド](comparison-guide.md)を参照してください。

## 表示と比較

- **画面の切り替え**：「画面」で申請一覧・入力フォーム・ダッシュボードを切り替えます。デザイン、単独／左右の表示、表示幅、各画面の状態（一覧の検索条件・フォーム入力・ダッシュボードの集計条件）は維持されます。
- **単独表示**：「デザイン」で切り替えます。再読み込みはなく、検索条件・入力値・入力エラー・確認ステップなどの状態は維持されます。
- **左右比較**：2つのデザインを並べます。左右は個別に選択でき、「入れ替え」で交換します。一覧の検索条件、フォームの入力値・エラー・ステップ、ダッシュボードの集計条件は左右で共通です。どちらで操作しても他方に反映されます。
- **表示幅**：「自動」のほか 1280 / 1024 / 768 / 375px に固定できます。自動幅の左右比較では各画面を最低 600px で表示し、足りない分は比較エリアを横スクロールします。固定幅を選ぶとその幅を使います。各デザインは画面全体ではなく**枠の幅**に応じてレイアウトを切り替えます。

## 申請一覧

キーワードと処理状態で絞り込み、列見出しで並べ替え、行の操作から詳細を開きます。キーワードは受付番号・申請者名とふりがな・申請種別・担当課を対象に、空白区切りで AND 検索します。全角／半角、大文字／小文字、カタカナ／ひらがなの違いを吸収します。申請者の並べ替えはふりがな順です。

詳細の表示方法はデザインによって別ページ・行の展開・ドロワー・ダイアログに分かれます。ダイアログでは Esc で閉じ、Tab で内部の操作対象を移動できます。「新規申請」から入力フォームへ進めます。

## 入力フォーム

項目は申請者氏名・ふりがな・メールアドレス・電話番号（任意）・申請種別・希望日・申請内容・確認事項への同意です。「確認へ」で必須・形式・同意を検証し、エラーがなければ確認画面へ進みます。確認画面から編集へ戻ると入力値が維持され、「申請する」で完了画面へ進みます。

画面上部の「入力データ」から次の状態を呼び出せます。

- **入力例**：正常な入力例を設定します。
- **エラーを再現**：必須の未入力・ふりがな／メールの形式不正・未同意を含む入力を設定し、エラーを表示します。
- **クリア**：空の編集状態に戻します。

**フォームの入力内容は送信・保存されません。** URL・ブラウザ履歴・ストレージにも書かず、ページを開いている間だけメモリに保持します。再読み込みや URL の開き直しでは入力値・エラー・確認ステップを復元しません。

## ダッシュボードの操作

対象期間と担当課を各デザインのフィルター部品で切り替えると、KPI・グラフ・件数が連動して更新されます。「リセット」で既定の期間と全担当課へ戻します。

受付件数・処理待ち・処理完了の KPI、処理状態、申請種別の数値やリンクから、同じ条件の申請一覧へ移動できます。期間・担当課・種別・処理待ち／完了の条件は、一覧の「引き継いだ絞り込み」で確認・解除できます。個別の処理状態は一覧の状態フィルターに反映され、そちらで変更・解除します。この移動では、対象件数を集計と合わせるため既存の検索語を空にし、選んだ処理状態を設定します。集計条件を変えるだけでは、一覧の条件やフォーム入力は初期化されません。

## URL で共有と復元

「URLをコピー」で、画面・デザイン・表示モード・表示幅・一覧条件・ダッシュボードの集計条件を共有できます。URL を開き直すと同じ状態を復元し、ブラウザの戻る／進むでも共有対象の状態が切り替わります。既定値の多くは URL から省略されます。未対応の値は既定値や空の条件へ戻します。

フォーム入力は共有対象に含みません。一方、**一覧の検索語は `q` として URL に含まれます**。共有時には検索条件も確認してください。

| パラメータ | 内容 | 例 |
| --- | --- | --- |
| `screen` | 画面（省略時は申請一覧。`form`：入力フォーム、`dashboard`：ダッシュボード） | `screen=dashboard` |
| `design` | 単独表示のデザイン ID（`dads` / `carbon` / `fluent` / `govuk` / `uswds` / `plain` / `material3`） | `design=govuk` |
| `mode`, `left`, `right` | 左右比較と左右のデザイン | `mode=compare&left=dads&right=carbon` |
| `width` | 表示幅（`1280` / `1024` / `768` / `375`） | `width=1024` |
| `q` | キーワード | `q=保育` |
| `status` | 処理状態（`received` / `reviewing` / `returned` / `approved` / `rejected`） | `status=reviewing` |
| `sort`, `order` | 並べ替えの列（`id` / `applicant` / `type` / `receivedAt` / `status`）と向き（`asc` / `desc`） | `sort=id&order=asc` |
| `detail` | 表示中の申請の受付番号 | `detail=2026-01041` |
| `period`, `dept` | ダッシュボードの集計条件（対象期間 `fy` / `h1` / `q2` / `m3`、担当課） | `period=q2&dept=市民課` |
| `lperiod`, `ldept`, `ltype`, `lgroup` | 一覧へ引き継いだ絞り込み（期間・担当課・申請種別・`pending` / `done`） | `lperiod=q2&lgroup=pending` |

例：`?design=material3`、`?screen=form&design=material3`、`?screen=dashboard&mode=compare&left=material3&right=dads&period=q2`。公開サイトの URL の末尾に付けて利用できます。

## ダッシュボードの集計

集計ロジックは [`dashboard.js`](../site/assets/js/dashboard.js) に 1 つだけあり、各デザインはその結果を表示します（同じ条件なら同じ数値）。一覧も同じ判定（`filterByScope`）で絞り込むため、ダッシュボードの数値から開いた一覧の件数は集計と一致します。基準日は固定（2026年10月12日）で、実際の日付には依存しません。

| 指標 | 計算方法 |
| --- | --- |
| 受付件数 | 受付日が対象期間内で、担当課が条件に一致する申請の数 |
| 処理待ち | 受付済・審査中・補正依頼の合計 |
| 処理完了 | 承認済・却下の合計 |
| 処理完了率 | 処理完了 ÷ 受付件数 |
| 各割合 | 件数 ÷ 受付件数（小数第 2 位を四捨五入して小数第 1 位まで。受付件数 0 のときは「—」。端数処理のため合計が 100% にならない場合がある） |

グラフは外部ライブラリを使わず、棒グラフは `ol` / `ul` の HTML/CSS、円・折れ線は SVG で描きます。円グラフは `role="img"` と値入りのラベルを持ち、折れ線の SVG は読み上げから隠して隣のリストで月と値を示します。積み上げ棒にも内訳のラベルがあり、すべての値を文字でも表示して、色だけに頼らない構成です。

### 対象期間

各期間はサンプルデータ用に固定されています。「直近3か月」も実際の日付からの相対期間ではありません。

| 値 | 表示名 | 集計する受付日の範囲（両端を含む） |
| --- | --- | --- |
| `fy` | 令和8年度（4月〜）・既定 | 2026-04-01〜2026-10-31 |
| `h1` | 上半期（4月〜9月） | 2026-04-01〜2026-09-30 |
| `q2` | 第2四半期（7月〜9月） | 2026-07-01〜2026-09-30 |
| `m3` | 直近3か月（8月〜10月） | 2026-08-01〜2026-10-31 |

実装とテストの場所は[開発資料](development.md#構成と状態管理)を参照してください。
